# Generated Output Reference

This document describes the **exact structure** of code generated by `l10n_mapper_generator`. Use it as the authoritative reference.

## Output File

| Input | Output |
|-------|--------|
| `app_localizations.dart` | `app_localizations.mapper.dart` |

The generator produces a `.mapper.dart` file alongside your Flutter-generated localization file. Configure the input in `build.yaml`:

```yaml
targets:
  $default:
    builders:
      l10n_mapper_generator:l10n_mapper_builder:
        generate_for:
          - lib/localization/gen-l10n/app_localizations.dart
        options:
          l10n: true
          locale: true
          parseL10n: true
          useNamedParameters: false
          message: "Translation key not found!"
```

## Generated Structure

### 1. BuildContextExtension

Extension on `BuildContext` providing `l10n`, `locale`, `lookup`, `parseKey`,
and `parseL10n`:

```dart
extension BuildContextExtension on BuildContext {
  AppLocalizations get _localizations => AppLocalizations.of(this)!;
  AppLocalizations get l10n => _localizations;
  Locale get locale => Localizations.localeOf(this);

  String parseKey(AppLocalizationsKey key) {
    final localizations = AppLocalizations.of(this)!;
    return localizations.parseKey(key);
  }

  String parseL10n(
    String translationKey, {
    List<Object>? arguments,
    Map<String, Object?>? namedArguments,
  }) {
    final localizations = AppLocalizations.of(this)!;
    return localizations.parseL10n(
      translationKey,
      arguments: arguments,
      namedArguments: namedArguments,
    );
  }
}
```

When `message` is `null`, the return type is `String?` instead of `String`.

### 2. AppLocalizationsExtension

Extension on `AppLocalizations` with typed lookup/parse helpers plus
switch-based raw-key dispatch:

```dart
extension AppLocalizationsExtension on AppLocalizations {
  Object? lookup(AppLocalizationsKey key) {
    return lookupKey(
      key.rawKey,
      arguments: key.arguments,
      namedArguments: key.namedArguments,
    );
  }

  Object? lookupKey(
    String key, {
      List<Object>? arguments,
    Map<String, Object?>? namedArguments,
  }) {
    return switch (key) {
      'localeName' => localeName,
      'cashierDeposit' => cashierDeposit,
      'cashierMinimumDeposit' => switch ((arguments, namedArguments)) {
        ([final amount, final currency], _) =>
          cashierMinimumDeposit(amount, currency),
        (_, {'amount': final amount, 'currency': final currency}) =>
          cashierMinimumDeposit(amount, currency),
        _ => throw ArgumentError(
          'cashierMinimumDeposit requires arguments: amount, currency',
        ),
      },
      'ecPop_message' => switch ((arguments, namedArguments)) {
        ([final errorCode], _) => ecPop_message(errorCode),
        (_, {'errorCode': final errorCode}) => ecPop_message(errorCode),
        _ => throw ArgumentError(
          'ecPop_message requires arguments: errorCode',
        ),
      },
      _ => null,
    };
  }

  String parseKey(AppLocalizationsKey key) {
    final result = lookup(key);
    if (result == null) {
      return 'Translation key not found!';
    }
    return result as String;
  }

  String parseL10n(
    String translationKey, {
      List<Object>? arguments,
    Map<String, Object?>? namedArguments,
  }) {
    final result = lookupKey(
      translationKey,
      arguments: arguments,
      namedArguments: namedArguments,
    );
    if (result == null) {
      return 'Translation key not found!';
    }
    return result as String;
  }
}
```

**Key benefits of switch-based approach:**
- **Tree-shakeable** — unused translation keys can be eliminated by the compiler
- **Zero allocation** — no map creation, no caching, no closures
- **Type-safe** — parameter types validated at generation time
- **No memory leaks** — no static cache holding references to `AppLocalizations`
- **Direct dispatch** — no `Function.apply`, compiler can inline
- **Optional named dispatch** — `useNamedParameters` enables placeholder-name
  matching for generated cases

**Nullable mode** (when `message` is `null`): Returns `String?`; key-not-found returns `null` instead of the fallback message.

## Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `l10n` | `bool` | `true` | Generate `l10n` getter on `BuildContext` |
| `locale` | `bool` | `true` | Generate `locale` getter on `BuildContext` |
| `parseL10n` | `bool` | `true` | Generate `parseL10n` and `lookupKey` on `AppLocalizations` |
| `useNamedParameters` | `bool` | `false` | Accept `namedArguments` keyed by generated parameter names |
| `message` | `String?` | `null` | Fallback when key not found. If set, returns `String`; if `null`, returns `String?` |
| `classNames` | `String` | `"AppLocalizations"` | Comma-separated class names to generate mapper for |

## Usage

```dart
// Simple keys (getters)
final text = context.parseKey(AppLocalizationsKeys.cashierDeposit);

// Parameterized keys (methods) - generated factories expose the right names
final text2 = context.parseKey(
  AppLocalizationsKeys.cashierMinimumDeposit(
    amount: 100,
    currency: 'USD',
  ),
);

// Direct on AppLocalizations (e.g. in tests)
final text3 = localizations.parseKey(AppLocalizationsKeys.cashierDeposit);

// Dynamic lookup without raw strings
final raw = localizations.lookup(
  AppLocalizationsKeys.cashierMinimumDeposit(
    amount: 100,
    currency: 'USD',
  ),
);
```

## Import

Import both the Flutter-generated localization file and the mapper:

```dart
import 'package:your_app/localization/gen-l10n/app_localizations.dart';
import 'package:your_app/localization/gen-l10n/app_localizations.mapper.dart';
```

The mapper file adds extensions; it does not modify `app_localizations.dart`.
